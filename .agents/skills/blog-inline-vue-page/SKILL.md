## 确定页面范围

从用户请求提取验证目标、输入、操作和可观察结果。路径未指定时选择简短的小写 kebab-case slug，并在 `views/labs/` 下检查是否已有同名页面。存在同名页面时检查其用途，不直接覆盖无关内容。

用户已经要求实现时，完成页面文件；不只返回代码片段或开发方案。只有用户明确要求先给方案时停留在方案阶段。缺少会改变功能含义的必要信息时集中询问，并继续不依赖答案的工作；普通布局、组件名和路径选择按项目约定落实。

优先使用当前 Vue、UnoCSS 和浏览器能力完成一个完整交互。默认使用页面内状态；仅按任务需求增加持久化、共享模块或外部接口。发现必须新增依赖时列出包名和原因，不自动安装，也不留下依赖未安装却声称可用的实现。

## 生成页面

1. 新建页声明 `layout: page`、`title`、`description`，正文提供标题、必要操作说明、验证目标和预期结果。已有页保留其布局与相关内容。
2. 单页逻辑写为内联 SFC，使用 `<script setup lang="ts">`、`<template>` 和按需添加的 `<style scoped>`。组件名使用同页唯一的 PascalCase 标识符。
3. 默认在定义位置自动插入组件；需要指定位置、props 或 `ClientOnly` 时采用手动放置。
4. 实现核心输入、操作和结果展示；需要重复试验时提供重置或等效操作。错误和边界输入给出与任务相关的结果。
5. 需要资源时使用 `views/public/`；出现实际跨页复用时再抽取共享模块。普通页面不写入文章生成数据，不新增全局组件注册。

围栏首行必须使用以下合法 JSON 形式：

````md
```vue {"component":true,"name":"ExamplePanel"}
````

上述是围栏首行示意，实际页面须补齐 SFC 内容和结束围栏。该方式自动插入组件，不再手写 `<ExamplePanel />`。

手动放置时使用 `{"component":true,"name":"ExamplePanel","lazy":true}`，在正文写 `<ExamplePanel />`，必要时包在 `<ClientOnly>` 中。`lazy` 仅控制插入位置。

本地模块用 `@/` 别名导入，依赖用包名；虚拟 SFC 不保留 Markdown 目录，不能假定相对导入会按页面位置解析。浏览器 API 在挂载后或事件中访问，卸载时清理监听器、计时器、观察器和动画帧。`ClientOnly` 不保证顶层静态 import 在服务端安全。

样式使用组件类名、scoped 和现有主题变量，适配窄屏与暗色。类型命名和导出遵循项目规范。具体模板与语法说明复用知识库，不在 skill 内维护另一套完整模板。

## 交付与验证

完成编辑后通过源码阅读核对围栏配置、组件插入次数、导入路径和生命周期。遵循根目录执行约束，不主动跑测试、构建、类型检查、lint、格式化或 git diff。

用户明确要求运行或查看效果时，完成授权范围内的本地服务与浏览器操作。开发、构建命令会重建文章符号链接并写生成数据，执行前确认相关路径。不能运行的检查明确说明原因；不能把预期结果当作已观察结果。

交付时列出页面文件、站内路由、关键操作、预期结果和实际验证范围。所有产物保留本地，不提交或部署。只有用户要求导航、索引或收录控制时才扩展这些功能。
